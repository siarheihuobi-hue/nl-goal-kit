NL GOAL — начните здесь

Версия 0.3 • 26.11.2026 • Рабочий комплект для пользователей NL GOAL

Ответственный за мастер-комплект: владелец NeuroLab. Назначение: внедрение управления результатом в одном действующем проекте. Метод проходит практическую проверку; сокращение сроков, расходов и хождения по кругу не гарантируется.

Состав: 00 — Начните здесь; 01 — Методология NL GOAL; 02 — Команды для запуска; 03 — Hermes — установка; 04 — Установка с нуля. Внутренние клиентские материалы в комплект не входят.

Если вы впервые

Начните с документа 04 — Установка с нуля. Он проведёт по первому проекту без предыдущей версии.

Если вы уже работали с NL GOAL

Обновите все пять документов до v0.3, сохранив карты, отчёты и данные проектов.

Порядок внедрения

Прочитайте пять файлов текущего релиза. Используйте единую команду из [README](../README.md) и [протокол внедрения](../INSTALL.md). Выберите один проект, согласуйте GOAL, маршрут и полномочия; проверьте MD/HTML и ярлык, получите доказательства и приёмку.

Не удаляйте карты, отчёты и данные проектов. Укажите Проводнику новую версию и попросите оценить изменения для текущей работы.

Справка по интерфейсу

Дополнение 15.11.2026 — второй контур внедрения: существующая нейрокоманда в VS Code

Методология NL GOAL не ограничивается GPT-проводником. После согласования GOAL владелец может передать его непосредственно оркестратору или проектной команде в VS Code. Оркестратор отвечает за корректную маршрутизацию и общий механизм карты; проектная команда — за содержание, исполнение и доказательства. Команда сама выбирает технический маршрут. Проводник помогает сформулировать и принять результат, но не обязан вести каждую техническую итерацию.

Для внедрения в существующую команду используйте новый раздел 7 документа «02 — Команды для запуска NL GOAL v0.3». Сначала изучаются действующие правила и источники; затем вносятся необходимые безопасные минимальные изменения; конфликты, существенные риски и нехватка полномочий выносятся владельцу. Не копируйте всю методологию в каждый проект и не создавайте дубликаты HTML-карт. Документ 01 содержит принципы для VS Code и критерии внедрения. Обновление карт — постоянная обязанность при существенных изменениях состояния, а не разовая задача.

Если у вас уже есть независимый проверяющий с доступом к рабочей среде, используйте его в отдельном диалоге. ACP и отдельная база знаний не обязательны.
